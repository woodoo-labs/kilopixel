TEST 41 — GRADIENT CACHE BUG INVESTIGATION

The gradient cache only invalidates when the gradient config object reference or u changes. If a shape's local geometry changes (animated w/h or polyline points), the cached CanvasGradient uses stale bounding box coordinates and misaligns.

EXPECTED: NO BUG
A — Moving rect via x attribute
The x attribute translates via CTM. getBoundingBox() ignores x/y — it's always in local space. Gradient cache stays valid. Gradient should follow the rect.

C — Animated polyline points
Polyline points animate → bounding box changes each frame. Gradient cache hits (static config) → gradient stays at t=0 bounding box. The gradient radial center drifts away from the shape's actual centroid.

How to read these tests: Test A (moving): gradient should always appear red→blue on the rect — the CTM handles positioning, local geometry is unchanged. Test B (width): when the rect is at its widest, you should see solid blue at both edges — the gradient covers only the initial narrow width. Test C (polyline): the radial gradient should stay roughly fixed while the triangle's apex moves — the centroid shifts but the gradient doesn't.

Root cause: createGradient() in shape.js caches on (_lastGradientConfig === styleValue && _lastGradientU === u). For static gradients on animated shapes, styleValue is always the same object reference (compiler staticCache) → cache always hits → bounding box recalculation never occurs.

Fix: Add bounding box dimensions to the cache key: _lastGradientW, _lastGradientH, _lastGradientL, _lastGradientT.
