Colors & Gradients

The foundational color systems for Kilopixel shapes. Learn how to apply standard solid colors, CSS variables, and generative linear and radial gradients to any shape's fill or stroke.

1. Named Colors & Hex Codes

Because Kilopixel renders directly to HTML5 Canvas, you can use any valid CSS color keyword (like tomato or transparent) or hexadecimal code (like #1e293b) for the fill and stroke attributes.

Stacking Order (Z-Index): Elements are drawn strictly in the order they appear in the HTML. The last element in the markup is drawn on top of the others.

<pxl-stage ratio="5 / 3">
  <pxl-layer>
    <!-- Circle 1 (Drawn First, at the bottom) -->
    <pxl-circle x="500" y="230" r="140" fill="tomato" stroke="#991b1b" strokewidth="10"></pxl-circle>
      
    <!-- Circle 2 (Drawn Second, in the middle) -->
    <pxl-circle x="420" y="370" r="140" fill="#38bdf8" stroke="royalblue" strokewidth="10"></pxl-circle>
      
    <!-- Circle 3 (Drawn Last, on top) -->
    <pxl-circle x="580" y="370" r="140" fill="#fbbf24" stroke="#b45309" strokewidth="10"></pxl-circle>
  </pxl-layer>
</pxl-stage>

2. RGB & RGBA

The rgb() and rgba() formats break colors down into their core numeric channels: Red, Green, and Blue (0-255). The rgba() variant adds a fourth Alpha channel (0.0 - 1.0) to control transparency, allowing overlapping shapes to blend together.

<pxl-stage ratio="5 / 3">
  <pxl-layer>
    <!-- Circle 1 (Red) -->
    <pxl-circle x="500" y="230" r="140" fill="rgba(255, 0, 0, 0.7)"></pxl-circle>
      
    <!-- Circle 2 (Green) -->
    <pxl-circle x="420" y="370" r="140" fill="rgba(0, 255, 0, 0.7)"></pxl-circle>
      
    <!-- Circle 3 (Blue) -->
    <pxl-circle x="580" y="370" r="140" fill="rgba(0, 0, 255, 0.7)"></pxl-circle>
  </pxl-layer>
</pxl-stage>

3. HSL & HSLA

The hsl() and hsla() formats use Hue (0-360), Saturation (0-100), and Lightness (0-100). HSL is especially powerful for generative graphics because you can easily animate the Hue channel over time using the t variable.

Golden Rule of hsla Colors: Never use % signs! By sticking to pure numbers (e.g., fill="hsl(120, 100, 50)"), you can seamlessly animate colors using math and time variables without triggering syntax errors. The engine handles all the CSS units behind the scenes.

Exception: If you choose to use Javascript backticks (template literals) for string interpolation (e.g., fill="`hsl(${t*90}, 100%, 50%)`"), your math and time variables are evaluated natively by JavaScript. Because this bypasses Kilopixel's formatting helpers, you must include the % signs manually so the final generated string is valid CSS.

<pxl-stage ratio="5 / 3">
  <pxl-layer>
    <!-- Circle 1 (Static HSL) -->
    <pxl-circle x="500" y="230" r="140" fill="hsl(0, 100, 50)"></pxl-circle>
      
    <!-- Circle 2 (HSLA with Alpha) -->
    <pxl-circle x="420" y="370" r="140" fill="hsla(120, 100, 50, 0.7)"></pxl-circle>
      
    <!-- Circle 3 (Animated Hue) -->
    <pxl-circle x="580" y="370" r="140" fill="hsl(t * 90, 100, 50)"></pxl-circle>
  </pxl-layer>
</pxl-stage>

Controls

This circle's Hue is driven by the time variable t. Adjusting the slider changes the multiplier, affecting how fast the colors cycle.

4. Linear Gradients

The linear() math helper generates high-performance linear gradients. The first argument defines the direction (either an angle in degrees or an [x1, y1, x2, y2] coordinate array where 0 to 1 represents the element's bounding box). The second argument is an array of colors (which distribute evenly) or explicit [offset, color] pairs.

The 0-to-1 Bounding Box: In Kilopixel, gradients are locked to the element's bounding box! The top-left corner of any shape is always exactly (0, 0), and the bottom-right is (1, 1). This guarantees that if you move, scale, or stretch your shape, the gradient stretches seamlessly with it â€” no complex trigonometry required!

In the diagrams below, the blue coordinates represent the fixed corners of the shape's invisible bounding box. The purple vectors represent the actual [x1, y1, x2, y2] array driving the gradient's direction through that box.

True Geometric Angles: When you provide an angle in degrees instead of an array, Kilopixel bypasses the 0-to-1 corner mapping entirely! It projects a geometrically perfect angle from the center of the shape and calculates the exact distance needed to cover the corners. This means a 45Â° gradient is always drawn at a strict 45-degree angle on the screen, even if the bounding box is a wide rectangle!

<pxl-stage ratio="5 / 3">
  <pxl-layer>
    <!-- Rect 1 (Angle Driven) -->
    <pxl-rect x="140" y="300" w="200" h="280" fill="linear(45, [0, '#ff0055', 0.45, '#ff0055', 0.55, '#00ffcc', 1, '#00ffcc'])"></pxl-rect>
      
    <!-- Rect 2 (Explicit Offsets) -->
    <pxl-rect x="380" y="300" w="200" h="280" fill="linear(90, [0, '#000', 0.5, '#f00', 1, '#000'])"></pxl-rect>

    <!-- Rect 3 (Coordinate Vector) -->
    <pxl-rect x="620" y="300" w="200" h="280" fill="linear([0, 0, 1, 1], ['#ffea00', '#ff00a0'])"></pxl-rect>
      
    <!-- Rect 4 (Animated Angle) -->
    <pxl-rect x="860" y="300" w="200" h="280" fill="linear(t * 90, ['#8A2387', '#E94057', '#F27121'])"></pxl-rect>
  </pxl-layer>
</pxl-stage>

Controls

This gradient uses explicit offsets. The slider moves the red color stop back and forth between 0.0 and 1.0.

This rectangle's gradient angle is driven by the time variable t. Adjusting the slider changes the multiplier, affecting how fast the gradient spins.

5. Radial Gradients

The radial() helper generates radial gradients. The engine uses a farthest-corner architecture: a radius of 1 perfectly and intuitively stretches to the extreme tips of any shape's bounding box. You can pass a simple number, an array of 3 coordinates [x, y, r] to offset the center, or an array of 6 coordinates [x0, y0, r0, x1, y1, r1] to unlock full 3D spotlight effects.

The Farthest-Corner Guarantee: Kilopixel gradients are mathematically locked to the element's bounding box. For radial gradients, the engine dynamically calculates the distance to the farthest corner so that a radius of 1 perfectly and intuitively stretches to the extreme tips of any shape.

In the diagrams below, the solid blue box represents the invisible bounding box, while the purple vector represents the generated radius targeting the farthest corner.

<pxl-stage ratio="5 / 3">
  <pxl-layer>
    <!-- Rect 1 (Standard Radius) -->
    <pxl-rect x="140" y="300" w="200" h="280" fill="radial(1, ['#ff0055', '#00ffcc'])"></pxl-rect>
      
    <!-- Rect 2 (3-Arg Offset Center) -->
    <pxl-rect x="380" y="300" w="200" h="280" fill="radial([0.2, 0.2, 1], ['#ffea00', '#ff00a0'])"></pxl-rect>

    <!-- Rect 3 (6-Arg 3D Spotlight) -->
    <pxl-rect x="620" y="300" w="200" h="280" fill="radial([0.2, 0.2, 0.1, 0.8, 0.8, 1.2], ['#8A2387', '#E94057', '#F27121'])"></pxl-rect>
      
    <!-- Rect 4 (Hard Border Trick) -->
    <pxl-rect x="860" y="300" w="200" h="280" fill="radial(1, [0, '#000', 0.95, '#00f', 0.95, '#fff', 1, '#fff'])"></pxl-rect>
  </pxl-layer>
</pxl-stage>
