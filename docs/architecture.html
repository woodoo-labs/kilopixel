Architecture & Performance

Kilopixel isn't just a wrapper around the Canvas API; it's a multi-tier compiled reactivity engine. It is built with zero-GC (Garbage Collection) patterns to ensure a consistent 60fps framerate without stuttering.

The Scene Graph

A Kilopixel scene consists of a specific hierarchy:

  • <pxl-stage> (The Root Container): Owns the requestAnimationFrame loop, creates a base <canvas> in the Shadow DOM, and monitors pointer events and screen resizing.
  • <pxl-layer> (Compositing Units): Each layer owns its own isolated <canvas> and is placed absolutely over the stage. This enables independent clearing, hidden optimizations, and blending.
  • <pxl-group> (Transform Containers): Does not own a canvas. It draws into its parent's context. Groups can nest infinitely, adding their transforms to the stack.
  • Shapes (The Primitives): <pxl-circle>, <pxl-rect>, <pxl-polyline>, etc. These actually execute the drawing commands.

Performance: The Three-Tier Compiler

In a typical animated scene, 60-70% of the attributes on elements are entirely static (e.g., fill="red", radius="30").

Kilopixel features a Fast Path Compiler that classifies expressions progressively. It checks: Hex Colors → CSS Functions → Booleans → Numbers → Words → Expressions → Code Blocks.

If an attribute is static (like a number or hex color), the framework pays zero runtime evaluation cost for it. Dynamic mathematical expressions are wrapped into highly optimized inner closures evaluated each frame.

Performance: Dirty-Flag Rendering

The engine only renders what needs to be rendered:

  • If a layer has no animated attributes and no internal state changes, it pays zero per-frame render cost.
  • Only layers flagged as isDirty = true are cleared and re-drawn.
  • If a layer is hidden and already cleared, it completely skips the render pipeline.

Performance: Zero-GC Patterns

To prevent the browser's Garbage Collector from pausing your animations, the core rendering loop reuses objects rather than allocating new ones:

  • Array Management: Subscriber lists and coordinate caches use flat arrays and Float32Arrays, manipulated in-place.
  • Bounding Boxes: Shape bounding boxes are pre-allocated objects that are mutated directly instead of being recreated.
  • Gradients: Gradient descriptors are lightweight objects, and actual CanvasGradient instances are heavily cached across frames.
