Expressions and Math

Kilopixel properties aren't just strings; they are highly optimized mathematical expressions evaluated directly by a custom compiler at 60 frames per second.

Smart Returns

Any string passed to an attribute that evaluates math will automatically be wrapped in a return statement by the engine.

Simple Expressions

<pxl-rect fill="t % 2 < 1 ? 'red' : 'blue'" />

Full Blocks

If your string explicitly contains the word return, the compiler allows you to write full JavaScript block logic:

<pxl-rect fill="if (t % 2 < 1) { return 'red'; } else { return 'blue'; }" />

(Note: Strings inside JS expressions must be quoted, e.g., text="'Hello'").

Animation Time (t)

The framework provides a global t variable.

  • t is ALWAYS evaluated in Seconds, not milliseconds.
  • For example, t * 60 means a rate of 60 per second (e.g., 60 degrees of rotation per second).

Built-In Time Drivers

Kilopixel includes built-in oscillators and time drivers to make animations effortless. Because these drivers internally handle time in seconds, you can just pass them the frequency you want:

  • wave(freq): Sine wave oscillating between -1 and 1. wave(2) completes a cycle every 2 seconds.
  • glide(freq): Smooth ease-in-out ping-pong animation between 0 and 1.
  • bounce(freq): Bouncing motion between 0 and 1.
  • loop(freq): Linear loop from 0 to 1.
  • yoyo(freq): Linear ping-pong between 0 and 1.
  • pulse(freq): Spiky ping-pong animation.
  • strobe(freq): Blinking boolean logic.
  • glitch(freq): Random noise / jumping values.

Colors & Gradients

The engine injects global JavaScript functions for handling colors safely without needing template literals: hsl, hsla, rgb, rgba, linear, and radial.

Because they use parentheses, they bypass the Fast Path string checker and are safely evaluated dynamically at 60fps. They NEVER need backticks.

1. hsl(h, s, l) and hsla(h, s, l, a)

Perfect for color cycling:

<pxl-circle fill="hsl(t * 50, 100, 50)" />

2. Linear Gradients

  • linear(angle, ['color1', 'color2']): Linear angles use true CSS geometry. An angle (like 45) will push gradient endpoints outside the bounding box if necessary to maintain the physical line angle.
  • linear([x1, y1, x2, y2], ['color1', 'color2']): Explicit coordinates are proportional to the shape's bounding box. 0 is the top/left edge and 1 is the bottom/right edge.

3. Radial Gradients

  • radial(radius, ['color1', 'color2']): Radius is relative to bounds. Use 1 to stretch to the edge (not 0.5).
  • radial([cx, cy, r], ['color1', 'color2']): Explicit center coordinates and radius overrides.

4. Color Stops

Color arrays can be simple ['red', 'blue'] or explicitly offset-mapped: [0, 'red', 1, 'blue']

Because evaluation happens at 60fps, returning a new array literal on every frame is perfectly fine!

Filters & Template Literals

The Fast Path intercepts static filters (like filter="drop-shadow(0 0 10px red)") and returns them as strings instantly. This is extremely fast and bug-free.

However, because of the Fast Path, you cannot put raw math directly inside a static filter string. To animate a filter, you MUST wrap the entire attribute in JavaScript backticks to force evaluation:

<!-- Correct way to animate a filter: -->
<pxl-circle filter="`drop-shadow(0 0 ${wave(2)*15}px red)`" />
