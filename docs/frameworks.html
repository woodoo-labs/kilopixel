Frameworks

Kilopixel's elements are standard custom elements. A framework sets their attributes or properties and listens to their events with its own syntax: there is no adapter and no wrapper component. Kilopixel is tested with React 19, Vue 3.5 and Tailwind CSS 4; other frameworks use the same DOM operations.

1. Setup

Load pxl.min.js once, with a <script> tag in the <head> of the page that hosts the app (index.html), before the app's own script. The elements are then defined before the framework renders them.

<!-- index.html of the app, in <head>, before the app's script -->
<script src="pxl.min.js"></script>

Most frameworks need no further setup. The exceptions:

  • React and Preact: nothing to set up. Use React 19 or later: React 18 passes every value to a custom element as an attribute string, so arrays and objects arrive as text.
  • Vue 3: tell the template compiler that tags starting with pxl- are custom elements. Without it, Vue still renders them but warns about unknown components.
  • Angular: add CUSTOM_ELEMENTS_SCHEMA to the schemas of each component that uses Kilopixel's elements.
  • Svelte, Solid, Lit, Alpine, htmx: nothing to set up.
  • Tailwind CSS: nothing to set up; utilities work on stages, layers, groups and shapes (section 6).
// Vue 3, with the in-browser build
const app = createApp(App);
app.config.compilerOptions.isCustomElement = (tag) => tag.startsWith('pxl-');

// Vue 3 with Vite: vite.config.js
export default {
  plugins: [vue({
    template: { compilerOptions: { isCustomElement: (tag) => tag.startsWith('pxl-') } }
  })]
};

// Angular: the component that uses Kilopixel's elements
@Component({
  selector: 'app-chart', templateUrl: './chart.html', schemas: [CUSTOM_ELEMENTS_SCHEMA]
})
export class ChartComponent {}

TypeScript: without type definitions, TypeScript rejects <pxl-circle r={50}> as an unknown tag. Download kilopixel.d.ts and the file for the framework, and put both in the project's source folder, where the tsconfig.json includes them:

  • React 19: kilopixel-react.d.ts
  • Preact 11: kilopixel-preact.d.ts
  • Solid 2: kilopixel-solid.d.ts
  • Vue 3: kilopixel-vue.d.ts, read by Volar and vue-tsc
  • Svelte 5: kilopixel-svelte.d.ts, read by svelte-check
  • Angular and plain TypeScript: kilopixel.d.ts alone

Every attribute is then typed: a number accepts numbers and expression strings, keyword attributes like linecap suggest their keywords, and reading a property returns its current value.

const circle = document.querySelector('pxl-circle'); // PxlCircleElement
circle.r = 50;                 // or an expression: 'sin(t) * 10 + 50'
const radius: number = circle.r;

A custom shape needs a declaration of its own, which extends PxlShapeAttributes and PxlShapeElement (Custom Shapes).

Inside the Project

The framework files import the framework's own types (react, vue, …), so they must sit inside the project, next to its node_modules. They are generated from the engine with each version; download them again when you update pxl.min.js.

2. Values: Properties and Attributes

Every attribute of a Kilopixel element is also a JavaScript property. React 19, Vue, Preact and Svelte set the property when an element has one; Angular [x], Lit .x and Solid prop:x always do. Numbers, arrays and objects then arrive as they are.

function Gauge({ value, data }) {
  return (
    <pxl-stage ratio={5 / 3}>
      <pxl-layer>
        {/* Left: Dial, a number from props */}
        <pxl-circle x={250} y={300} r={value} fill="#f97316"></pxl-circle>

        {/* Right: Chart, points as [x, y] pairs */}
        <pxl-polyline points={data} stroke="#3b82f6" strokewidth={4}></pxl-polyline>

        {/* Bottom: Label, shown as written */}
        <pxl-text x={500} y={550} size={27} align="center" text={`Value: ${value}`}></pxl-text>
      </pxl-layer>
    </pxl-stage>
  );
}

The same in a Vue template:

<pxl-circle :x="250" :y="300" :r="value" fill="#f97316"></pxl-circle>
<pxl-polyline :points="data" stroke="#3b82f6" :strokewidth="4"></pxl-polyline>
<pxl-text :x="500" :y="550" :size="27" align="center" :text="`Value: ${value}`"></pxl-text>
  • Numbers, Arrays, Objects: stored as they are, without parsing: r={value}, linedash={[20, 10]}, points={[[0, 0], [100, 50]]} (flat [x0, y0, x1, y1] works too). To change an array, pass a new one: a change made to the same array in place isn't seen.
  • Strings: read like attribute text, so x="300 + sin(t) * 100" animates and fill="hsl(200, 50%, 40%)" is a color.
  • Text: a string set as text is shown exactly as written, never read as an expression. Expressions in text stay available in plain markup.
  • Removing a Value: undefined or null sets the default, like a removed attribute.
  • Last Change Wins: setting a property doesn't change the attribute in the markup. Set each value one way, not both.
  • Reading Back: el.x returns the current value, also of an animated expression.

Values That Change Every Frame

Numbers, colors, text and points cost almost nothing to update, even in every frame. A new expression string is compiled each time it changes: for continuous motion, write t into the markup (rotate="t * 45"), or pass numbers.

Strings Are Code

Except for text, a string value is read as an expression, as in an attribute. Never pass untrusted text, such as user input, to these values. Colors from data are safe when they are #hex, rgb(), or hsl() with percentages: they are not compiled.

3. Events

Shapes and groups get DOM events, like elements on the page: the shape under the pointer is the event's target, and the event bubbles through its groups, its layer and the stage to the page. A framework's own event syntax works on them, for direct listeners (Vue, Angular, Lit, Svelte) and for listeners at the root (React).

{/* Right: Button, a group with a rect and a label */}
<pxl-group x={700} y={300} style={{ cursor: 'pointer' }} onClick={() => setCount((c) => c + 1)}
  onPointerEnter={() => setHover(true)} onPointerLeave={() => setHover(false)}>
  <pxl-rect w={300} h={120} r={16} fill={hover ? '#2563eb' : '#3b82f6'}></pxl-rect>
  <pxl-text size={27} fill="#ffffff" align="center" baseline="middle" text="Add"></pxl-text>
</pxl-group>
<!-- Vue -->
<pxl-group :x="700" :y="300" :style="{ cursor: 'pointer' }" @click="count++"
  @pointerenter="hover = true" @pointerleave="hover = false">…</pxl-group>

<!-- Angular -->
<pxl-circle [x]="250" [y]="300" [r]="value" (click)="add()"></pxl-circle>

<!-- Svelte -->
<pxl-circle x={250} y={300} r={value} onclick={add}></pxl-circle>
  • Clicks and Presses: click, dblclick, contextmenu, pointerdown, pointerup, mousedown, mouseup. Each action arrives once, with the shape as target. Over empty space the browser's own event arrives unchanged, with the layer as target.
  • Hover: pointerover, pointerout, pointerenter, pointerleave and their mouse versions, with relatedTarget. A group gets pointerenter and pointerleave only when the pointer crosses its edge, not when it moves between its shapes.
  • Moves: pointermove and mousemove on the shape under the pointer, once per frame.
  • Buttons: put the shapes of a button (a rect and its label) in a <pxl-group> and listen on the group. A click on the label then counts for the button.
  • Propagation: stopPropagation() keeps the event from the groups and elements around the shape; preventDefault() reaches the browser, so on contextmenu it keeps the browser's menu closed.
  • Declarative Handlers: pxl-on-click and the other pxl-on-* attributes are listeners for the same events, so they can be mixed with a framework's listeners.

4. Cursor and Pointer

  • Cursor: comes from CSS, as for elements. Set cursor on a shape, a group or a layer (style={{ cursor: 'pointer' }}, Tailwind cursor-pointer); the shapes inside a group inherit it. A shape with a pxl-on-click, pxl-on-down or pxl-on-up handler shows the hand by default. A framework listener doesn't add one, like a <div> with a click listener.
  • Decorations: every visible shape catches the pointer. A shape drawn on top of a button that shouldn't take its clicks gets pointer-events: none; pointer-events: auto on a shape inside brings that shape back.
  • Pointer Position: event.clientX and clientY are the browser's. offsetX and offsetY equal them on shape events, because shapes have no box on the page. In stage units, read ref.<stage>.mouseX in an expression, or stage.values.mouseX in JavaScript.
  • Dragging: drag code that calls event.target.setPointerCapture() works on shapes. On touch screens, set touch-action: none on the stage, or the browser scrolls instead.

5. Components

  • Unique IDs: ids are global for the whole page (ref.<id>), so every instance of a component needs its own. Generated ids need cleaning: ref reads a hyphen as a minus sign.
  • Hover Styling: CSS :hover never matches a shape. Use isHovered in an expression, or state from pointerenter and pointerleave.
  • Mounting: shapes, layers and whole stages can be mounted, moved and unmounted at any time, also in keyed lists.
function Planet() {
  // React's useId() gives ids like «r1»: keep letters and digits only
  const id = 'planet' + useId().replace(/[^a-zA-Z0-9]/g, '');
  return (
    <pxl-circle id={id} x={500} y={300} r={80}
      fill={`ref.${id}.isHovered ? '#2563eb' : '#3b82f6'`}>
    </pxl-circle>
  );
}

6. Tailwind and CSS

  • Utilities Win: Kilopixel's default styles have the lowest priority, so a class like w-1/2 sizes a stage; the stage keeps its aspect ratio.
  • Pointer and Cursor Classes: cursor-pointer, cursor-default, pointer-events-none and pointer-events-auto work on stages, layers, groups and shapes. hidden and invisible on a layer hide it and take it out of hit testing.
  • No Hover Variants: hover: variants never match a shape; use isHovered.
  • The Stage's Style: the stage keeps its aspect ratio in its inline style. Setting single style properties is fine (React style, Vue :style); replacing the whole style attribute removes the ratio, so use classes for the stage instead.

7. Server Rendering

Server-rendered markup hydrates without warnings: the browser adds no nodes inside Kilopixel's elements (each layer keeps its canvas in a shadow root), and the stage measures itself once it is in the page. Loading Kilopixel during server rendering does nothing, and loading it twice keeps the first copy. Kilopixel isn't tested with Next.js or Nuxt yet.

8. Known Limits

  • Hover in CSS: :hover and Tailwind hover: never match a shape.
  • Positions on the Page: getBoundingClientRect() of a shape is empty, so a tooltip at a shape needs its position computed from the stage.
  • Keyboard: shapes can't take keyboard focus yet.
  • Global IDs: every instance of a component needs its own ids (section 5).
  • Capture Listeners: a capture listener above the stage (React onClickCapture) sees the browser's click, with the layer as target, before the shape's click.
  • Angular with zone.js: every frame of an animated stage triggers change detection. Create animated stages outside Angular's zone (NgZone.runOutsideAngular()), or use zoneless change detection.
  • Packages: no npm package yet; the type definitions are downloads (section 1).

9. Live Events Playground

The stage below listens with plain addEventListener(), the way every framework does underneath, and logs each event as it arrives. Hover and click the circle and the button, and compare with the controls. The circle's radius is set as a property, as frameworks set it.

<pxl-stage ratio="5 / 3">
  <pxl-layer>
    <!-- Left: Circle, its radius set as a property -->
    <pxl-circle id="circle" x="250" y="300" fill="#ffedd566" stroke="#f97316" strokewidth="4">
    </pxl-circle>

    <!-- Right: Button, a group with a rect and a label -->
    <pxl-group id="button" x="700" y="300" style="cursor: pointer">
      <pxl-rect w="300" h="120" r="16" stroke="#3b82f6" strokewidth="4"
        fill="ref.button.isHovered ? '#bfdbfe' : '#dbeafe66'"></pxl-rect>
      <pxl-text size="27" fill="#3b82f6" align="center" baseline="middle" text="Button"></pxl-text>
    </pxl-group>
  </pxl-layer>
</pxl-stage>
