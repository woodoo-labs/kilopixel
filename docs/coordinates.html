Coordinate System

Understanding the coordinate system is the key to mastering Kilopixel. Unlike standard Canvas APIs which use physical pixels, Kilopixel uses a responsive, logic-based coordinate space designed for declarative markup.

1. Stage <pxl-stage>

To ensure graphics are fully responsive across all screen sizes, every Kilopixel <pxl-stage> has a fixed logical width of 1000. The height is dynamically computed based on the ratio attribute.

Values as percentages: Because the logical width is always 1000, you can mentally read coordinates and sizes as percentages of the Stage's width with one decimal place. For example, a circle with r="200" will have a radius spanning exactly 20.0% of the stage's width, and a line with strokewidth="10" will be exactly 1.0% thick.

A <pxl-stage> has a CSS width of 100%, meaning it will always automatically adapt to horizontally fill its parent element. To control the physical Stage width, you simply adjust the width of its parent container.

In the example below, try moving the ratio slider to see how the coordinate system adapts: the logical width remains fixed at 1000 across all formats, while the logical height is dynamically computed from the aspect ratio. No matter how large or small your physical screen is, the Stage Origin is always (0, 0)!

<!-- Try resizing the container or dragging the ratio slider -->
<div style="width: 100%;">
  <pxl-stage ratio="5 / 3">
    <!-- Insert layers (containing shapes and groups) here -->
  </pxl-stage>
</div>

2. Layer <pxl-layer>

Working directly in global Stage coordinates can become rigid. Instead, a <pxl-layer> allows you to create an independent, movable local coordinate space:

  • Global Positioning: The Layer itself is positioned relative to the Stage's top-left Origin.
  • Layer Center: The Layer's x and y attributes define its own internal (0, 0) Layer Center.
  • Nesting Spaces: Drag the Layer sliders below. Notice how the entire local grid moves. Any Shape you place inside this Layer will be drawn relative to this moving Layer Center, rather than the static Stage Origin.
<!-- Moving the Layer Center to the middle of the Stage -->
<pxl-stage ratio="5 / 3">
  <pxl-layer x="500" y="300">
    <!-- Insert shapes and groups here -->
  </pxl-layer>
</pxl-stage>

3. Shape, e.g. <pxl-circle>

In Kilopixel, the x and y attributes of any Shape define its center point relative to its parent Layer or Group.

Because Shapes are nested inside Layers, their final screen position is compounded. In the example below, the circle is placed at local (350, 150). But because its parent Layer is also shifted to (400, 200), you can see how the Shape's final visual position on the Stage is perfectly Offset from both reference points!

<!-- Placing a Shape whose Center is at (350, 150) -->
<pxl-stage ratio="5 / 3">
  <pxl-layer x="400" y="200">
    <pxl-circle x="350" y="150" r="250" stroke="#f97316"></pxl-circle>
  </pxl-layer>
</pxl-stage>

4. Rotation rotate

In Kilopixel, applying rotation is incredibly simple. When you rotate a Shape, it spins around its x and y Center by default.

However, it is important to understand the difference between Layer and Shape rotation:

  • Layer Rotation: Rotating a <pxl-layer> spins the entire coordinate space inside that Layer around the Layer Center. The Shape's relative coordinates do not change, but the local space it lives in spins together with the Layer.
  • Shape Rotation: Rotating a Shape (such as a <pxl-ellipse>) only spins that specific Shape around its own Center, leaving the rest of the Layer untouched.

Look for the pulsing orange indicator dot () on the controls below — try spinning the Layer and Ellipse sliders to see this difference in real time!

<!-- An ellipse spinning perfectly around its center point -->
<pxl-stage ratio="5 / 3">
  <pxl-layer x="500" y="300" rotate="0">
    <pxl-ellipse 
      x="200" y="150" 
      rx="250" ry="100" 
      rotate="20" stroke="#f97316">
    </pxl-ellipse>
  </pxl-layer>
</pxl-stage>

5. Offset dx and dy

This is where Kilopixel's coordinate system becomes incredibly powerful. The dx and dy attributes (where "d" stands for delta) offset the shape from its x and y Center.

Because this offset happens inside the shape's local coordinate system, any rotation applied will cause the shape to orbit the Center instead of just spinning in place.

<!-- A rectangle orbiting its Pivot Point -->
<pxl-stage ratio="5 / 3">
  <pxl-layer x="200" y="150" rotate="0">
    <pxl-rect 
      x="300" y="150" 
      dx="150" dy="150" 
      rotate="0" 
      w="100" h="100" stroke="#f97316">
    </pxl-rect>
  </pxl-layer>
</pxl-stage>

6. Reference ref.*

Any element with an id can be instantly referenced by other Shapes. You can declaratively link to its attributes using the ref.* prefix, and Kilopixel will automatically keep them perfectly in sync.

This allows for true cross-attribute linking. In this example, if you change the Master shape, the others react instantly. The Mirror perfectly mirrors its X position (1000 - ref.master.x), while the Reactor links its size and rotation to the Master's position!

<!-- Linking attributes across different shapes -->
<pxl-stage ratio="5 / 3">
  <pxl-layer x="0" y="0" rotate="0">
    <!-- 1. Master Shape (You control this) -->
    <pxl-rect id="master" x="250" y="200" w="100" h="100" rotate="0" stroke="#f97316"></pxl-rect>

    <!-- 2. Mirror Shape (Moves in reverse) -->
    <pxl-rect id="mirror" 
      x="1000 - ref.master.x" 
      y="ref.master.y" 
      w="100" h="100" 
      rotate="-ref.master.rotate" 
      stroke="#3b82f6">
    </pxl-rect>

    <!-- 3. Reactor Shape (Spins and scales) -->
    <pxl-rect id="reactor" 
      x="500" y="450" 
      w="ref.master.x / 5" 
      h="ref.master.x / 5" 
      rotate="ref.master.x" 
      stroke="#22c55e">
    </pxl-rect>
  </pxl-layer>
</pxl-stage>

7. Variables <pxl-var>

Sometimes you don't want to bind to a visual shape. You want a "headless" state variable that controls multiple elements at once, much like state management in React or Vue.

The <pxl-var> element is invisible, but any shape can reactively reference its value. In this example, three variables control the entire geometric composition:

<!-- Variables act as global state for the canvas -->
<pxl-stage ratio="5 / 3">
  <pxl-layer x="500" y="300" rotate="0">
    <!-- Global State -->
    <pxl-var id="hue" value="250"></pxl-var>
    <pxl-var id="spread" value="120"></pxl-var>
    <pxl-var id="size" value="150"></pxl-var>

    <!-- Shapes bound to state -->
    <pxl-circle dx="ref.spread.value" r="ref.size.value" fill="hsla(ref.hue.value + 25, 80, 60, 0.6)" rotate="0"></pxl-circle>
    <pxl-circle dx="ref.spread.value" r="ref.size.value" fill="hsla(ref.hue.value + 142, 80, 60, 0.6)" rotate="120"></pxl-circle>
    <pxl-circle dx="ref.spread.value" r="ref.size.value" fill="hsla(ref.hue.value + 217, 80, 60, 0.6)" rotate="240"></pxl-circle>
  </pxl-layer>
</pxl-stage>

8. Cross-Space Projection toLocal()

The true power of toLocal() is cross-space affine projection. It allows you to perfectly track an element nested deep inside rotating or scaled layers, without writing any trigonometry.

  • Layer Independence: You can place shapes inside completely different, independently transforming layers.
  • The Link: By using toLocal(ref.target, 'x'), Kilopixel calculates the target's global position and automatically translates it into your current coordinate space. It returns exactly the x and y values your shape needs to align perfectly.
  • The Magic: Kilopixel's spatial reactivity engine automatically tracks matrix changes. If a layer rotates or moves, it instantly alerts any element tracking its children to update!
<pxl-stage ratio="5 / 3">
  <!-- Two independent rotating layers with their own shapes -->
  <pxl-layer id="layer1" x="350" y="250" rotate="0">
    <pxl-circle id="circle1" x="-150" y="-150" r="100" stroke="#f97316"></pxl-circle>
  </pxl-layer>

  <pxl-layer id="layer2" x="650" y="350" rotate="0">
    <pxl-circle id="circle2" x="150" y="150" r="100" stroke="#3b82f6"></pxl-circle>
  </pxl-layer>

  <!-- A line perfectly tracking two shapes inside different rotating layers -->
  <pxl-layer>
    <pxl-line 
      x1="toLocal(ref.circle1, 'x')" y1="toLocal(ref.circle1, 'y')" 
      x2="toLocal(ref.circle2, 'x')" y2="toLocal(ref.circle2, 'y')" 
      stroke="#ff00ff">
    </pxl-line>
  </pxl-layer>
</pxl-stage>

9. Animations (Time t, Math & Time Drivers)

Kilopixel has a native animation loop that evaluates all variable expressions at 60 FPS. By using the built-in t variable (time in seconds), injected math functions (like sin and cos), and normalized time drivers (like loop(d)), you can create incredibly complex, smooth animations declaratively.

In this example, we use sin(t) and cos(t) with independent X and Y frequencies to draw a Lissajous curve. We also use the native hsl() scope function combined with the loop(d) time driver to elegantly cycle the orb's color across the color wheel exactly once every 10 seconds!

<pxl-stage ratio="5 / 3">
  <pxl-layer x="500" y="300" rotate="0">
    <!-- Pure Math: Lissajous curve using sine waves -->
    <pxl-var id="hue" value="loop(10) * 360"></pxl-var>
    <!-- Note: shadowcolor safely self-references its own stroke -->
    <pxl-circle id="oscillator"
      x="sin(t * 2) * 300" 
      y="cos(t * 3) * 150" 
      r="40" 
      fill="hsla(ref.hue.value, 100, 60, 0.4)" 
      stroke="hsl(ref.hue.value, 100, 60)" 
      strokewidth="4"
      shadowcolor="ref.oscillator.stroke" 
      shadowblur="20">
    </pxl-circle>
  </pxl-layer>
</pxl-stage>
